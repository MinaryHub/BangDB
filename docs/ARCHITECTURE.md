## 1. Pager (`internal/pager`)

SQLite의 WAL 모드와 같은 방식의 **다중 버전 페이지 저장소**입니다.

- 파일은 4096바이트 페이지의 배열이고, 각 페이지의 **마지막 4바이트는 CRC32 체크섬**입니다(내용은 4092바이트). 디스크(DB 파일·WAL)에서 읽을 때마다 검증하고, 불일치 시 `ErrCorrupt`를 반환합니다.
- **0번 페이지는 헤더**: 매직 + 포맷 버전(3), 페이지 크기, 페이지 수, free list 헤드, 메타 슬롯 8개(0 = 카탈로그 루트, 1 = AUTOINCREMENT 시퀀스 트리), 커밋 순번(Seq), DB 식별자(DBID).
- **커밋(그룹 커밋)**: 쓰기 트랜잭션의 `View`(copy-on-write 오버레이)에 모인 변경 페이지를 WAL 끝에 `(pgno, page)* + [marker, seq, count, crc32]` 그룹으로 추가하고(fsync 없이, `PrepareCommit`) 페이지 버전 목록에 등록합니다. 다음 writer는 곧바로 이 상태 위에서 시작할 수 있고, 리더에게는 아직 보이지 않습니다. 이어서 `Flush`가 그때까지 준비된 **모든 커밋을 fsync 1회로** 내구화한 뒤 순서대로 공개합니다. 커밋의 카탈로그(meta)는 준비 시점에 함께 넘겨져 같은 순간에 공개됩니다. DB 파일은 이 시점에 바뀌지 않습니다.
- **스냅샷 읽기**: 리더는 `Snapshot`(커밋 seq S 고정)을 잡고, 각 페이지에 대해 "seq ≤ S인 가장 최신 버전, 없으면 DB 파일"을 읽습니다. 그래서 리더와 커밋이 서로를 기다리지 않고, 리더는 중간 상태를 보지 않습니다. 버전 이미지는 64MiB까지 메모리에 두고 그 이상은 WAL에서 다시 읽습니다.
- **체크포인트**: 목표 = min(열린 스냅샷들의 seq, 최신 seq). 페이지마다 목표 이하의 최신 버전을 DB 파일에 쓰고 fsync한 뒤 그 버전들을 목록에서 제거합니다. 그 페이지들은 모든 리더에게 WAL 버전이 보이는 상태이므로 파일 덮어쓰기가 리더와 충돌하지 않습니다. 버전이 모두 비면 WAL을 0바이트로 되돌립니다. WAL이 1,000페이지를 넘으면 커밋 직후 자동 실행되며, 오래 열린 스냅샷이 있으면 WAL이 그만큼 커집니다.
- **복구**: `Open` 시 WAL에서 체크섬이 맞는 완전한 커밋 그룹 중 DB 파일 헤더의 seq보다 큰 것만 순서대로 적용하고, 잘린 그룹 이후는 버립니다(체크포인트 도중 크래시도 멱등하게 복구).
- **지연 페이지 인코딩**: 쓰기 뷰는 B+트리가 수정한 페이지를 디코드된 노드(`pager.Lazy`)로 들고 있다가 커밋할 때(또는 `Read`로 바이트가 필요할 때) 한 번 인코딩합니다. 같은 페이지를 여러 번 고치는 트랜잭션은 인코딩을 한 번만 합니다. 세이브포인트는 그 페이지를 처음 건드릴 때 노드 복사본을 undo에 보관합니다.
- **세이브포인트**: 문장 실행 전에 undo 로그를 시작하고, 이후 처음 수정되는 페이지의 이전 오버레이 값을 기록합니다. 실패 시 역순으로 되돌립니다. 비용은 트랜잭션 크기가 아니라 해당 문장이 수정한 페이지 수에 비례합니다.
- 새 파일 생성·`rename` 후 디렉터리도 fsync합니다.
- **암호화(선택)**: 키를 주면 0번을 제외한 모든 페이지를 DB 파일·WAL에 쓸 때 AES-256-XTS(tweak = 페이지 번호)로 암호화하고 읽을 때 복호화합니다(`pager/crypt.go`). 체크섬은 암호화 전에 계산되어 페이지 안에 함께 암호화되므로, 복호화 후 CRC 검증이 잘못된 키·손상을 잡습니다. 헤더는 포맷 버전 4와 키 확인 값을 평문으로 기록합니다. 메모리의 페이지 버전·캐시·복제 프레임은 평문이므로 위 구조는 그대로입니다.
- **통계**: `Pager.Stats()` — 커밋·fsync·체크포인트 수와 시간, 디스크 읽기와 캐시 적중, WAL 크기, 열린 스냅샷과 그 지연. 엔진의 `DB.Stats()`가 문장·락 대기·커밋 시간과 함께 노출합니다.
- 검증: 무작위 커밋/스냅샷/체크포인트/재시작 모델 테스트, failpoint 크래시 테스트, 체크섬 변조 테스트, `kill -9` 반복 테스트(루트 패키지 `TestCrashTorture`).

## 2. B+트리 (`internal/btree`)

- 리프: `[type][n][next]` + `(klen key flag (vlen val | total firstOverflowPage))*`
- 내부 노드: `[type][n][child0]` + `(klen key child)*`; `children[i]`에는 `keys[i]` 미만, `children[i+1]`에는 이상인 키가 들어갑니다.
- 값이 700바이트를 넘으면 overflow 페이지 체인에 저장 → 리프 한 칸 최대 ~1.2KB로 제한되어 분할이 항상 성공합니다.
- 분할은 바이트 기준(가변 길이 셀 대응). **루트 분할 시 루트 페이지 번호를 유지**하므로 카탈로그에 루트 번호를 고정 저장할 수 있습니다.
- 삭제 후 노드가 페이지의 1/4보다 작아지면 형제와 합치고(한 페이지에 들어가면, 빈 페이지는 free list로), 아니면 항목을 고르게 나눕니다. 자식이 하나 남은 루트는 그 자식을 흡수해 높이를 줄입니다(루트 번호 유지).
- `Builder`는 정렬된 입력을 페이지당 90%까지 채워 아래에서 위로 트리를 만듭니다 (VACUUM).
- **노드 캐시**: 디코드된 노드를 Pager의 캐시에 **페이지 이미지(불변 바이트 슬라이스)의 주소**를 키로 보관합니다. 엔트리가 이미지를 참조하므로 주소가 재사용될 수 없고, 커밋·체크포인트로 이미지가 바뀌면 자연히 다른 키가 됩니다. 캐시된 노드는 여러 리더가 공유하므로 쓰기 경로는 복사본(`loadMut`)을 수정합니다. 쓰기 뷰는 방금 인코딩한 노드를 기억해 같은 페이지에 대한 연속 삽입에서 디코드를 생략합니다.

## 3. 값과 인코딩 (`internal/value`)

- 값 = Go 타입 `nil | int64 | float64 | string | []byte`.
- **행 레코드**: `uvarint(n)` + 각 값 `[tag][payload]` (정수는 zig-zag varint).
- **순서 보존 키**: 정수는 부호 비트를 뒤집은 big-endian, 실수는 IEEE 비트 변환, 문자열/BLOB은 `0x00 → 0x00 0xFF` 이스케이프 + `0x00 0x01` 종료 (prefix-free). 바이트 비교 = 값 비교.
- 테이블 트리 키 = `rowid`(8바이트), 값 = 행 레코드.
- 인덱스 트리 키 = `key(컬럼값) || rowid`, 값 없음. 동일 값의 모든 엔트리가 같은 prefix를 공유하므로 동등 검색은 prefix 스캔, UNIQUE 검사는 "같은 prefix에 다른 rowid가 있는가"입니다. collation이 있는 컬럼은 접힌 값(NOCASE는 소문자화)으로 키를 만듭니다.
- **긴 키**: 키 부분이 495바이트를 넘으면 `앞 495바이트 || 0x00 || 전체 키의 FNV-64 해시`로 저장합니다. 자르기는 순서를 보존하므로 같은 앞부분을 가진 키들은 연속된 "그룹"이 되고, 그룹 안은 해시 순입니다. 전체 키 동등 검색은 해시까지 포함해 찾고 행 값을 비교해 확정, 부분 키·범위 검색은 그룹 접두사로 찾고 필터가 재확인, 정렬 스캔은 그룹 단위로 값 순 재정렬합니다.

## 4. 카탈로그 (`internal/engine/catalog.go`)

- 메타 슬롯 0의 B+트리에 `t\0<table>`, `i\0<index>`, `v\0<view>`, `g\0<trigger>`, `h\0<closure>` → JSON 으로 저장. 테이블 항목에 CHECK(SQL 텍스트)와 외래 키가 들어가며, 로드 시 CHECK는 컴파일되고 FK는 부모 테이블의 `referencedBy` 목록으로 연결됩니다.
- 커밋된 카탈로그는 불변이고, DDL을 실행하는 트랜잭션은 복제본을 수정합니다. 커밋 시 포인터만 교체되므로 리더는 락 없이 일관된 스키마를 봅니다.

## 5. SQL 처리

1. **파싱**: 손으로 작성한 lexer + 재귀 하강 파서 → AST. 파싱 결과는 SQL 문자열 기준으로 캐시(512개)됩니다. AST는 실행 중 변경되지 않습니다.
2. **바인딩/컴파일**: `scope`(FROM 절의 모든 컬럼 + 테이블별 숨은 rowid)를 기준으로 식을 `func(*env) (any, error)` 클로저로 컴파일합니다. 집계 함수는 집계 슬롯 참조로 바뀝니다.
3. **플래닝** (`plan.go`):
   - WHERE를 AND 단위로 분해하고, 각 조건을 참조하는 테이블 중 가장 뒤 레벨로 **push-down** (LEFT JOIN 대상 테이블의 WHERE 조건은 NULL 확장 이후 평가).
   - 레벨마다 사용 가능한 조건 중에서 점수로 접근 경로 선택: rowid 동등 > UNIQUE 인덱스 전체 동등 > 복합 인덱스 선행 컬럼 동등(+ 다음 컬럼 IN/범위) > rowid IN > 인덱스 IN > rowid 범위 > 인덱스 범위 > OR 조건의 인덱스 합집합 > (조인 안쪽) 해시 조인 > 전체 스캔. 조인의 안쪽 테이블은 바깥 테이블 값을 키로 한 인덱스 lookup이 가능합니다. 비교의 collation이 컬럼(인덱스)과 같을 때만 인덱스를 씁니다.
   - ORDER BY가 첫 테이블의 rowid·인덱스 순서와 같으면(역방향 포함) 정렬을 생략하고 LIMIT에서 바로 멈춥니다. 아니면 LIMIT이 있을 때 top-K만 유지합니다.
   - 서브쿼리: 비상관은 문장당 1회 실행 후 캐시, 상관은 바깥 행마다 실행(바깥 컬럼은 `outerCtx` 체인으로 참조). 서브쿼리를 포함한 조건은 마지막 필터로 평가합니다.
   - **플랜 캐시**: 실행 중 상태가 없는 SELECT 플랜(서브쿼리·파생 테이블·뷰·해시 조인 제외)은 파싱된 문장과 카탈로그 포인터를 키로 재사용합니다. DDL은 카탈로그를 새로 만들므로 자동 무효화됩니다.
   - 접근 경로는 후보를 좁히기만 하고 원래 조건은 항상 다시 평가하므로 타입이 섞인 비교에서도 결과가 정확합니다 (`TestIndexMatchesScan`이 무작위로 인덱스 결과 = 풀스캔 결과임을 검증).
4. **실행**: 조인 → 필터 → (집계: 해시 그룹핑) → HAVING → 프로젝션 → DISTINCT → 정렬 → OFFSET/LIMIT. 정렬/집계/DISTINCT가 없으면 LIMIT에 도달하는 즉시 스캔을 멈춥니다.
   - **트랜잭션 spill** (`pager/spill.go`): 쓰기 트랜잭션이 바꾼 페이지가 `TxMemory`(기본 64 MiB)를 넘으면 행 경계(`SpillPoint`)에서 임시 파일로 옮깁니다. 페이지는 WAL 프레임과 같은 형태(CRC 봉인·암호화)로 저장하고, 읽기는 메모리 → spill 파일 → 커밋 순으로 찾습니다. savepoint 되돌리기는 페이지별 spill 위치도 함께 복원합니다(파일은 덧붙이기만 하므로 옛 이미지가 남아 있음). 커밋 때 spill 페이지는 메모리에 다시 올리지 않고 4 MiB 단위로 WAL에 복사하며, 복제 구독자가 있을 때만 WAL에서 다시 읽어 복제 로그에 넘깁니다.
   - **외부 정렬** (`spill.go`): 정렬 버퍼가 `SortMemory`를 넘으면 정렬된 run을 임시 파일에 쓰고 마지막에 k-way 병합합니다(안정 정렬). DISTINCT는 기억한 키가 한도의 절반을 넘으면 나머지 행을 값 순으로 정렬해 인접 중복을 제거하고, GROUP BY는 메모리 그룹이 한도를 넘으면 이후 새 그룹의 행을 그룹 키 순으로 정렬해 한 그룹씩 집계합니다.
5. **DML**: UPDATE/DELETE는 대상 행을 먼저 모은 뒤 수정합니다 (Halloween 문제 방지). 인덱스는 같은 트랜잭션 안에서 동기적으로 갱신됩니다. UPSERT는 충돌 행을 찾아 `excluded.*`와 함께 UPDATE로 바꿉니다.
6. **제약 조건** (`fk.go`): CHECK는 행 준비 단계에서 평가(NULL은 통과). FK는 행 단위로 즉시 검사: 자식 삽입·FK 컬럼 변경 시 부모 키(rowid 또는 UNIQUE 인덱스)를 확인하고, 부모 삭제·키 변경 시 자식(선행 컬럼이 FK인 인덱스가 있으면 사용)에 `CASCADE`/`SET NULL`/오류를 적용합니다. 연쇄 동작은 64단계로 제한합니다.
7. **뷰**: 조회 시 뷰의 SELECT를 실행해 파생 테이블처럼 사용합니다. 뷰·CTE·파생 테이블에 대한 바깥의 `열 = 상수`·`열 IN (상수…)` 조건은 본문에 먼저 넣습니다(`pushdown.go`: 일반 본문은 각 SELECT의 WHERE/HAVING, 재귀 CTE는 반복 단계가 그대로 넘기는 열만 시작 SELECT에).
8. **폐포 테이블** (`closure.go`): `CREATE CLOSURE`의 (anc, des, depth) 테이블. 원본 행 변경은 `insertRow`/`removeRow`/`updateRow`에서 트랜잭션의 "변경된 자식" 집합에 기록되고, 문장(트리거 본문 아닌)이 끝날 때 `afterDML`이 바뀐 노드와 그 아래를 위에서부터(Kahn) 재계산해 다른 행만 고칩니다. 순환이면 문장 실패(세이브포인트 복원). 일반 문장은 폐포 테이블에 쓸 수 없습니다.
9. **그래프 함수** (`graphfunc.go`): `graph_walk`/`graph_path`는 실행 맥락을 받는 테이블 값 함수로, 간선 테이블을 인덱스로 조회하거나 뷰를 문장마다 한 번 메모리로 읽어 너비 우선 탐색합니다.

## 6. 동시성 모델

| 락 | 보호 대상 |
|----|-----------|
| `writeSem` (용량 1 채널) | 쓰기 트랜잭션은 하나. busy timeout·context로 대기 |
| `Pager.flushMu` | WAL fsync는 한 번에 하나(그룹 커밋). 카탈로그는 커밋과 함께 공개되므로 스냅샷은 `Snapshot.Meta()`로 일관된 카탈로그를 얻음 |
| `swapMu` (RWMutex) | Pager 포인터 수명. 리더·커서는 R, replica 스냅샷 설치·`VACUUM` 교체·`Close`는 W |
| `Pager.mu` | 버전 목록, 페이지 캐시, 헤더 |

- 리더는 스냅샷에서 읽으므로 쓰기 트랜잭션·커밋·체크포인트와 서로 막지 않습니다(실측: 1.36초 걸리는 조회 동안 커밋 649건, 최대 대기 4.9ms).
- **스트리밍 커서**: 트랜잭션 밖의 단일 SELECT는 고루틴이 스냅샷 위에서 실행하며 채널로 행을 넘깁니다. 결과가 작다고 알려진 쿼리(단건 조회, LIMIT ≤ 256, GROUP BY 없는 집계)와 `QueryRow`는 고루틴 없이 즉시 실행합니다. `Close`, 끝까지 읽기, `DB.Close`, 또는 버려진 `Rows`의 finalizer가 실행을 멈추고 스냅샷을 해제합니다. 트랜잭션 안의 조회는 결과를 모아서 반환합니다.
- **취소**: 실행 컨텍스트가 256행마다 `ctx.Err()`를 확인합니다. 중단된 문장은 세이브포인트로 되돌려집니다.

## 7. 백업과 복제 (`internal/engine/replication.go`, `replication/`)

- 커밋마다 Pager가 변경 페이지 전체(헤더 포함)를 **Frame**으로 엔진의 복제 로그에 넘깁니다(구독자나 보관 설정이 없으면 보관하지 않음).
- **온라인 스냅샷**: Pager 스냅샷을 잡고(필요하면 같은 순간에 이후 커밋을 구독) 모든 페이지를 복사합니다. 스냅샷이라 일관되며 커밋을 전혀 멈추지 않습니다.
- `Backup`은 이 스냅샷을 로컬 파일로, replica 동기화는 같은 스냅샷을 TCP로 보낸 뒤 Frame 스트리밍을 이어갑니다.
- replica는 `CommitRaw`로 Frame을 자기 WAL을 거쳐 적용하므로 primary와 바이트 단위로 같은 파일을 유지하고, 스스로도 크래시에 안전합니다.
- **VACUUM**: 쓰기 락을 잡고 최신 커밋의 스냅샷에서 모든 트리(테이블·인덱스·시퀀스·카탈로그)를 `Builder`로 새 파일에 다시 쓴 뒤, 리더가 끝나기를 기다려 파일을 교체합니다. 커밋 순번은 이어지고 DBID는 새로 발급되며, 연결된 구독자는 끊겨 replica가 스냅샷으로 재동기화합니다.
- 자세한 내용은 [REPLICATION.md](REPLICATION.md).

## 8. 저장 방식 (`internal/store`)과 확장 지점

- 실행기는 행과 인덱스 항목을 `store.TableStore`(rowid → 행)와 `store.IndexStore`(정렬된 바이트 키)로만 다룹니다. 테이블마다 카탈로그에 저장 방식 이름(`store`, 기본 `""` = B+트리)이 기록되고, `store.Lookup`으로 찾은 `Kind`가 루트 페이지에서 저장소를 엽니다.
- 저장소의 상태는 모두 Pager 페이지에 있으므로 트랜잭션·스냅샷·WAL·체크포인트·백업·물리 복제를 그대로 공유합니다.
- 새 저장 방식을 추가하려면 `store.Kind`를 구현해 `store.Register`로 등록하고 `storetest.TestTableStore`를 통과시킨 뒤 `CREATE TABLE … USING <이름>`으로 씁니다. 인메모리 최적화(4단계)와 시계열 chunk(5단계)가 이 지점에 들어갑니다.
- **휘발성 저장 방식** (`memory`): 데이터를 페이지 대신 Pager의 **객체 슬롯**(`View.Obj/SetObj`, 키 = 저장소의 루트 페이지)에 둡니다. 슬롯은 페이지와 같은 규칙을 따릅니다 — View의 변경은 커밋 공개 전까지 비공개, 스냅샷은 자기 커밋의 슬롯을 봄, 다음 writer는 준비된 커밋 위에서 시작, 세이브포인트 복원. WAL·파일에는 쓰지 않습니다.
  - 값은 `internal/memtree`의 영속 B+트리(경로 복사)입니다. 커밋된 트리는 불변이라 스냅샷이 그대로 공유하고, 트랜잭션 안에서는 View의 변경 토큰과 같은 토큰으로 만든 노드만 제자리 수정합니다. View는 세이브포인트마다 새 토큰을 쓰므로 되돌아갈 수 있는 상태는 절대 수정되지 않습니다.
  - 행은 행 레코드(`[]byte`)로 보관합니다 — 포인터가 없어 GC가 행 내용을 추적하지 않고 메모리도 작습니다.
  - 무결성 검사는 휘발성 저장소의 루트 페이지만 사용 중으로 계산하고 행·인덱스 일치는 인터페이스로 검사합니다. VACUUM은 새 루트 페이지를 할당하고 불변 트리를 그대로 넘깁니다.
- **시계열 저장 방식** (`timeseries`, `internal/store/timeseries.go`): 저장소가 행의 시각으로 rowid(`tick << k | seq`)를 정하고(`RowidAssigner`), 시간 조건을 rowid 범위로 바꿉니다(`TimeKeyer`) — 플래너는 이를 `accTimeRange` 접근 경로로, `ORDER BY 시간`은 rowid 순서로 처리합니다. B+트리 하나에 블록(0x01‖첫 rowid → 열 지향 압축, `tsblock.go`), 개별 행·덮어쓰기·삭제 표시(0x02‖rowid), 메타(0x03)를 둡니다. 스캔은 블록 행과 개별 항목을 rowid 순으로 병합합니다. 블록은 서로 겹치지 않고 봉인 후에는 범위 삭제 외에는 다시 쓰지 않습니다. 저장 방식 옵션은 `ConfigurableKind`로 검증·전달되며 카탈로그에 저장됩니다.
- 내구성 저장 방식의 무결성 검사 구조 검사와 VACUUM은 테이블 루트를 B+트리로 보고 직접 다룹니다. B+트리가 아닌 페이지 구조를 쓰는 kind를 넣을 때 `Kind`에 Check/Rebuild를 추가합니다.
- 루트 테스트를 다른 kind로 돌리기: `BANGDB_TEST_STORE=<kind> go test .` (`memory`면 파일 재오픈 후 데이터를 기대하는 테스트는 건너뜀) (시험용 `reversed` kind는 행 값을 뒤집어 저장해, 인터페이스를 우회하는 코드를 드러냅니다).
- `pager.Pager` 저장소(파일/메모리)를 교체하면 저장 매체를 바꿀 수 있습니다.
