# BangDB 아키텍처

```
 ┌───────────────────────────────────────────────────────────────┐
 │  bangdb (공개 API)      driver (database/sql)     cmd/bangdb (CLI) │
 └───────────────┬───────────────────────────────────────────────┘
                 │
 ┌───────────────▼───────────────────────────────────────────────┐
 │ internal/engine                                               │
 │   db.go      DB / Tx / Conn, 락, 문장 캐시, 세이브포인트           │
 │   catalog.go 스키마(테이블·컬럼·인덱스) ↔ 카탈로그 B+트리(JSON)      │
 │   plan.go    접근 경로 선택, 조건 push-down, nested-loop 조인        │
 │   select.go  SELECT/집계/정렬, INSERT/UPDATE/DELETE, EXPLAIN       │
 │   exec.go    DDL, 행·인덱스 유지, 제약 조건                          │
 │   expr.go    식 → 클로저 컴파일, 함수, 집계 상태                     │
 ├──────────────────────────────┬────────────────────────────────┤
 │ internal/sql                 │ internal/value                 │
 │  lexer → parser → AST        │  값 타입, 비교, 타입 변환          │
 │  FormatExpr (AST → SQL)      │  행 인코딩, 순서 보존 키 인코딩      │
 ├──────────────────────────────┴────────────────────────────────┤
 │ internal/btree   B+트리 (가변 길이 키/값, overflow 체인, 리프 연결)    │
 ├───────────────────────────────────────────────────────────────┤
 │ internal/pager   4KB 페이지, 커밋 상태 + View(트랜잭션 오버레이),     │
 │                  free list, WAL·크래시 복구, 페이지 캐시, 파일 락     │
 │                  저장소: 파일 또는 메모리(:memory:)                  │
 └───────────────────────────────────────────────────────────────┘
```

## 1. Pager (`internal/pager`)

- 파일은 4096바이트 페이지의 배열입니다. **0번 페이지는 헤더**: 매직, 페이지 크기, 페이지 수, free list 헤드, 메타 슬롯 8개(0번 = 카탈로그 루트).
- `Pager`는 **커밋된 상태**만 보관합니다 (파일 + 공유 클린 페이지 캐시, 또는 메모리 맵).
- `View`는 트랜잭션별 **copy-on-write 오버레이**입니다. 쓰기는 `dirty` 맵에만 들어가고 커밋 전까지 파일은 변하지 않습니다.
  - 그래서 롤백은 오버레이를 버리는 것으로 끝나고, 리더는 오버레이 없는 View로 커밋 상태를 그대로 읽을 수 있습니다.
- **세이브포인트**: 문장 실행 전에 undo 로그를 시작하고, 이후 처음 수정되는 페이지의 이전 오버레이 값을 기록합니다. 실패 시 역순으로 되돌립니다. 비용은 트랜잭션 크기가 아니라 해당 문장이 수정한 페이지 수에 비례합니다.
- **커밋 프로토콜** (redo WAL):
  1. 모든 dirty 페이지 + 헤더를 `<db>-wal`에 `[pgno][page]...[commit marker][count][crc32]` 형식으로 기록 후 fsync
  2. 페이지를 DB 파일에 기록 후 fsync
  3. WAL을 0바이트로 truncate
- **복구**: `Open` 시 WAL에 커밋 레코드와 CRC가 맞으면 재적용(멱등), 아니면 무시. 테스트(`pager_test.go`)에서 failpoint로 "WAL 기록 직후 크래시"와 "커밋 레코드가 잘린 WAL"을 검증합니다.

## 2. B+트리 (`internal/btree`)

- 리프: `[type][n][next]` + `(klen key flag (vlen val | total firstOverflowPage))*`
- 내부 노드: `[type][n][child0]` + `(klen key child)*`; `children[i]`에는 `keys[i]` 미만, `children[i+1]`에는 이상인 키가 들어갑니다.
- 값이 700바이트를 넘으면 overflow 페이지 체인에 저장 → 리프 한 칸 최대 ~1.2KB로 제한되어 분할이 항상 성공합니다.
- 분할은 바이트 기준(가변 길이 셀 대응). **루트 분할 시 루트 페이지 번호를 유지**하므로 카탈로그에 루트 번호를 고정 저장할 수 있습니다.
- 삭제는 재균형 없이 리프에서 제거만 합니다 (단순성 우선). 커서와 `Last()`는 빈 리프를 건너뜁니다.

## 3. 값과 인코딩 (`internal/value`)

- 값 = Go 타입 `nil | int64 | float64 | string | []byte`.
- **행 레코드**: `uvarint(n)` + 각 값 `[tag][payload]` (정수는 zig-zag varint).
- **순서 보존 키**: 정수는 부호 비트를 뒤집은 big-endian, 실수는 IEEE 비트 변환, 문자열/BLOB은 `0x00 → 0x00 0xFF` 이스케이프 + `0x00 0x01` 종료 (prefix-free). 바이트 비교 = 값 비교.
- 테이블 트리 키 = `rowid`(8바이트), 값 = 행 레코드.
- 인덱스 트리 키 = `key(컬럼값) || rowid`, 값 없음. 동일 값의 모든 엔트리가 같은 prefix를 공유하므로 동등 검색은 prefix 스캔, UNIQUE 검사는 "같은 prefix에 다른 rowid가 있는가"입니다.

## 4. 카탈로그 (`internal/engine/catalog.go`)

- 메타 슬롯 0의 B+트리에 `t\0<table>`, `i\0<index>` → JSON 으로 저장.
- 커밋된 카탈로그는 불변이고, DDL을 실행하는 트랜잭션은 복제본을 수정합니다. 커밋 시 포인터만 교체되므로 리더는 락 없이 일관된 스키마를 봅니다.

## 5. SQL 처리

1. **파싱**: 손으로 작성한 lexer + 재귀 하강 파서 → AST. 파싱 결과는 SQL 문자열 기준으로 캐시(512개)됩니다. AST는 실행 중 변경되지 않습니다.
2. **바인딩/컴파일**: `scope`(FROM 절의 모든 컬럼 + 테이블별 숨은 rowid)를 기준으로 식을 `func(*env) (any, error)` 클로저로 컴파일합니다. 집계 함수는 집계 슬롯 참조로 바뀝니다.
3. **플래닝** (`plan.go`):
   - WHERE를 AND 단위로 분해하고, 각 조건을 참조하는 테이블 중 가장 뒤 레벨로 **push-down** (LEFT JOIN 대상 테이블의 WHERE 조건은 NULL 확장 이후 평가).
   - 레벨마다 사용 가능한 조건 중에서 접근 경로 선택: rowid 동등 > UNIQUE 인덱스 동등 > 인덱스 동등 > IN 목록 > rowid 범위 > 인덱스 범위 > 전체 스캔. 조인의 안쪽 테이블은 바깥 테이블 값을 키로 한 인덱스 lookup이 가능합니다.
   - 접근 경로는 후보를 좁히기만 하고 원래 조건은 항상 다시 평가하므로 타입이 섞인 비교에서도 결과가 정확합니다 (`TestIndexMatchesScan`이 무작위로 인덱스 결과 = 풀스캔 결과임을 검증).
4. **실행**: nested-loop 조인 → 필터 → (집계: 해시 그룹핑) → HAVING → 프로젝션 → DISTINCT → 정렬 → OFFSET/LIMIT. 정렬/집계/DISTINCT가 없으면 LIMIT에 도달하는 즉시 스캔을 멈춥니다.
5. **DML**: UPDATE/DELETE는 대상 행을 먼저 모은 뒤 수정합니다 (Halloween 문제 방지). 인덱스는 같은 트랜잭션 안에서 동기적으로 갱신됩니다.

## 6. 동시성 모델

| 락 | 보호 대상 |
|----|-----------|
| `writeSem` (용량 1 채널) | 쓰기 트랜잭션은 하나. busy timeout으로 대기 |
| `commitMu` (RWMutex) | 리더는 문장 실행 동안 R, 커밋 반영 시 W |
| `Pager.mu` | 페이지 캐시/헤더 |

쓰기 트랜잭션은 자기 오버레이에만 쓰므로 리더와 충돌하지 않습니다. 리더가 멈추는 것은 커밋이 페이지를 파일에 반영하는 짧은 순간뿐입니다.

## 7. 확장 지점

- `pager.Pager` 저장소(파일/메모리)를 교체하면 저장 매체를 바꿀 수 있습니다.
- 실행기는 현재 `btree`를 직접 호출합니다(`exec.go`의 행/인덱스 유지, `plan.go`의 `scan`). 시계열·인메모리 전용 저장 구조를 붙이려면 이 부분을 `TableStore` 인터페이스로 추출하는 것이 첫 단계입니다. 자세한 내용은 [검토 문서](REVIEW-timeseries-inmemory.md)를 보세요.
