# 호환성 정책

BangDB는 데이터를 오래 보관하는 소프트웨어이므로, **디스크에 쓴 데이터는 이후 모든 버전에서 읽을 수 있어야 한다**는 것을 가장 강한 약속으로 둡니다.

## 1. 약속 (0.6 이후)

| 대상 | 현재 버전 | 약속 |
|---|---|---|
| 데이터 파일 | 포맷 3 (평문), 4 (암호화) | 이후 모든 버전이 그대로 연다. 포맷을 바꿀 때는 새 버전이 옛 파일을 **열 때 자동 변환**하거나 변환 명령을 제공한다. 되돌리기(새 파일을 옛 버전으로 열기)는 지원하지 않는다 |
| WAL | `BWL2` | 위와 같음. 업그레이드 전에 정상 종료(체크포인트)를 권장 |
| 카탈로그(스키마) | JSON, 페이지 안 | 위와 같음. 새 필드는 추가만 하고 의미를 바꾸지 않는다 |
| SQL 덤프 (`Dump`) | 텍스트 | 이후 버전의 `ImportSQL`이 읽는다 |
| 메모리 테이블 스냅샷 `<db>-mem` | `BMEM1` | 읽지 못하면 무시(메모리 테이블은 원래 휘발성) |
| PITR 아카이브 (`base-*.db`, `seg-*.bfa`) | `BFA1` | 이후 버전의 `Restore`가 읽는다 |
| 복제 프로토콜 | v2 | 버전이 다르면 연결을 거부한다(데이터 손상 없음). primary와 replica는 같은 버전으로 함께 올린다 |
| 서버 프로토콜 (`server`/`client`) | `BDB1` | 같은 0.x 안에서 유지. 바꿀 때는 새 매직으로 구분하고 거부 메시지를 준다 |
| HTTP API | 엔드포인트·JSON 형식 | 필드 추가만 하고 기존 필드의 의미를 바꾸지 않는다 |
| Go API | 0.x | 1.0 전까지 바뀔 수 있다. 바뀌면 CHANGELOG에 적는다. 1.0부터 semver |

## 2. 검증

- `compat_test.go`가 `testdata/compat/`의 **고정 파일**(이전 릴리스가 만든 포맷 3·4 DB)을 열어 같은 데이터를 읽는지, 무결성 검사·쓰기·덤프가 되는지 매 빌드(CI 3개 OS)에서 확인한다.
- 픽스처는 절대 다시 만들지 않는다. 포맷이 바뀌면 새 픽스처를 **추가**한다(`BANGDB_WRITE_FIXTURES=1`).

## 3. 업그레이드 절차 (권장)

1. 현재 버전으로 `db.Backup()` (또는 `.backup`)
2. 정상 종료 (WAL이 비워짐)
3. 새 버전으로 열기 → `PRAGMA integrity_check`
4. 복제 구성은 replica → primary 순서가 아니라 **함께** 올린다(프로토콜 버전이 맞아야 함)

## 4. 버전 표기

`주.부.커밋수` (예: 0.6.45). 기능 단계가 바뀌면 `VERSION`의 주.부를 올린다. 릴리스는 `v0.6.45` 같은 git 태그로 표시한다.
